# Outflows carry a final-value flag

An Outflow gains an `isFinal` flag (sheet column `is_final`), set on the outflow editor and off by default. It marks the amount as confirmed for the month. The Outflows list flags a not-final outflow with a ⚠️ before its name and, among the open outflows, orders it after the confirmed ones (paid outflows form a single bottom tier, sorted alphabetically); copies made by replicate-last-month always arrive not final. The point is the workflow after a replicate: variable amounts (the card bill, utilities) are collected behind the confirmed open obligations, visibly awaiting this month's real value, without changing any total.

We rejected deriving finality from paid status — an outflow can be paid before its value is confirmed, and a confirmed value can still be unpaid — and rejected a heavier "reviewed this month" workflow with its own screen or snapshot history for a marker this small. Extending the `outflows` tab is additive and uses the established header-rewrite migration (prd.md "Sheet Initialization"): an existing sheet gains the column on its header row, and rows read back not final until written again.
